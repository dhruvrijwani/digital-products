# Idea 05 · Fit Finder from Reviews (Standard Issue)

A denim product page (PDP) with a "Find my size" drawer. Two questions, plus a size signal mined from 40 reviews, produce a recommended size. One tap then selects that size on the page.

Standard Issue is an invented brand. Photos come from Pexels (free licence), chosen without visible brand tabs or labels. The 40 reviews are mock data generated for the demo.

## What the demo shows

**Product page**
- Gallery (a swipeable carousel on mobile), colour swatches and size pills (XXL sold out).
- A "Find my size" link, Add to cart, details, a size chart and a review section.
- The review section has the overall fit distribution bar, computed from all 40 reviews.

**Drawer**
- Slides in from the right with a staggered entrance. Progress dots and the connecting line animate between steps.

**Question 1: height and usual size**
- A height slider (150 to 205 cm) drives a live ruler that glides under a fixed needle, with a cm and ft/in readout.
- Usual-size pills (XS to XXL). "Next question" switches on once you pick one.

**Question 2: fit preference**
- Three illustrated cards: Snug, Regular and Relaxed, with SVG jeans silhouettes and hover states. The card is a keyboard radiogroup.

**Analysis**
- A short "Reading N reviews from people like you" moment: the count climbs to the number of matching reviewers while scan lines sweep.

**Result**
- Your usual size flips away and the recommended letter flips in.
- The confidence meter fills and counts up, with a one-line reason.

**Review-mined fit signal**
- A Runs small / True to size / Runs large bar animates to percentages computed in JS from reviewers near your height.
- Below it are three of the closest-height reviews, with the fit phrase highlighted by a marker sweep.

**Select size**
- Closes the drawer and scrolls to the size selector.
- Pre-selects the size with a ring animation and pulses Add to cart.
- The recommended pill keeps a "Recommended" tag.

**Retake**
- The result leaves in reverse order, the tag is removed and the quiz restarts at question 1.

**Mobile (<768px)**
- The drawer becomes a bottom sheet with a drag handle. Drag the header down to dismiss.

**Accessibility**
- Modal dialog with a focus trap, inert page behind it, Esc to close, and focus returned to the trigger.
- Labelled range input with `aria-valuetext`, radio groups for every choice, and a live region announcing the recommendation.

**Reduced motion**
- Flips, sweeps, scrolls and staggers become instant changes or short fades.

## How the recommendation works (mock heuristic, demo only)

This is **not** a fit model. It is a simple, transparent rule set in `recommend()` (`app.js`), meant to show the interaction:

1. **Find comparable reviewers.** Take reviews from people within ±5 cm of the shopper's height, widening by 3 cm at a time until at least 8 match.
2. **Compute the fit signal.** Count the shares saying runs small, true to size and runs large. Each review carries a `fit` label and a matching `fitPhrase`.
3. **Score the shift.** `lean = share(small) − share(large)`. Fit preference adds −0.45 (snug), 0 (regular) or +0.45 (relaxed). `score = lean × 1.4 + preference`.
4. **Pick the size.** A score of 0.5 or more means one size up from the usual size. A score of −0.5 or less means one size down. Anything else keeps the usual size.
5. **Confidence.** 50 + 34 × (share of the most common opinion) + up to 10 for sample size, capped at 96%.

**What real data a production version needs**
- **Order and return data:** the size bought, whether it was returned or exchanged, the return reason ("too small" or "too large"), and the size kept after an exchange. This is the strongest signal, far stronger than review text.
- **Review text and structured fit answers:** a fit rating on the review form, plus NLP on free text for phrasing variants ("snug in the thigh", "size down"). Reviewer height, weight or usual size should be collected as optional fields.
- **Garment measurements per size** (waist, hip, rise, inseam, leg opening), ideally per fabric. Rigid selvedge and stretch denim fit very differently.
- **The shopper's own history:** sizes they kept in comparable products.
- **Enough volume per size and height band,** with confidence shrunk toward "true to size" when data is thin.

## How to run

```bash
npx serve .          # from the repo root
# open http://localhost:3000/idea-05/
```

Opening `index.html` directly works too: it falls back to `data/product.js`, generated by `node tools/sync-data.mjs`. GSAP (core + ScrollToPlugin) loads from a CDN.

## File map

| File | Role |
| --- | --- |
| `index.html` | PDP shell and the fit-finder drawer markup |
| `styles.css` | Tokens, PDP, size pills, drawer, ruler, fit cards, result, fit bar, bottom sheet |
| `app.js` | Rendering, the recommendation heuristic, quiz flow and animations, select/retake, sheet drag |
| `data/product.json` | Product, sizes with measurements, and 40 reviews (size bought, height, fit label, phrase) |
| `assets/img/` | Gallery photos |

## Shopify mapping (later, not implemented)

| Prototype piece | Shopify home |
| --- | --- |
| "Find my size" link + drawer | Theme app extension **app block** placed in the product form (next to the variant picker), with an **app embed** for the drawer markup and JS |
| Size pills, recommended tag, pre-select | Theme's variant picker. The block sets the matching variant option and dispatches the theme's variant-change event (Dawn: `variant-selects` → `onVariantChange`). |
| Size measurements (waist, hip, inseam) | Product or variant metafields, e.g. `fit.waist_cm` on each variant, or a `size_chart` metaobject referenced by the product |
| Review fit fields (fit label, height, size bought) | Reviews app with custom questions, synced to a metaobject or read through the app's API |
| Fit signal + recommendation | App backend endpoint (app proxy `/apps/fit/recommend`) combining reviews with order/return data from the Admin API (`returns`, `orders.lineItems`) |
| Fit distribution on the PDP | Product metafield `fit.distribution` (JSON), refreshed nightly by the app, rendered by the block |
| Shopper's past sizes | Customer metafield `fit.preferred_sizes`, updated after kept orders (with consent) |
| Add to cart | Theme's existing product form (`/cart/add.js`) |
